# QA

## 什么时候用

- 前端页面、交互、脚本、工具链已经改完，要做真实验收
- 需要按严重程度记录问题，并复测闭环
- 用户关心“别只实现，要验证到位”

## 不什么时候用

- 还没完成实现
- 只是方案评审或代码走查

## 默认步骤

1. 明确本轮要测的入口、场景和成功标准。
2. 用真实证据验证：
   - 页面 / 浏览器行为
   - 命令输出
   - 日志
   - 截图
   - 测试结果
3. 把问题分为：
   - 阻塞
   - 重要
   - 可后续优化
4. 若发现问题，给出复现条件、影响范围、建议修法。
5. 修复后重新验证，明确哪些问题已关闭、哪些仍保留。

## 输出要求

- 结论必须基于证据
- 至少说明测了哪些入口
- 有问题时必须给优先级和复测状态
