# Plan Eng Review

## 什么时候用

- 已经有需求或草图，但还没开始实现
- 想先把架构、接口、状态流和边界情况过一遍
- 不想写完后才发现测试口径、失败路径、性能点没想清楚

## 不什么时候用

- 需求仍然很模糊，应先走 `office-hours`
- 已经进入代码排障，应优先走诊断或测试先行流程

## 默认检查面

1. 输入输出和职责边界
2. 调用链 / 数据流
3. 状态与异常路径
4. 边界条件和回退策略
5. 测试覆盖方式
6. 性能 / 成本 / 依赖风险
7. 这轮明确不做什么

## 默认步骤

1. 读取已有 spec / plan / tasks 或等价说明。
2. 找出最容易“看起来合理、做起来出事”的点。
3. 把风险归类为：
   - 可直接开工
   - 需要补说明
   - 当前不建议开工
4. 给出精简评审结论：
   - 通过项
   - 阻塞项
   - 建议补充
   - 最小验证方案

## 输出要求

- 优先短条目或表格
- 必须明确阻塞项
- 必须给出最小验证方案
- 如果评审不过，直接说不建议开工
